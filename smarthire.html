Overview

SmartHire is a medium-difficulty Linux box running an ML hiring platform. The attack chain involves registering a malicious MLflow model containing a pickle payload to get a reverse shell, then escalating to root by dropping a .pth file into a plugins directory that a sudo-accessible Python script loads via site.addsitedir().

Hosts
smarthire.htb — hiring platform frontend
models.smarthire.htb — MLflow backend (admin:password)

Recon

Standard nmap scan reveals two web services. The main app is a hiring platform where users upload CSV resumes to train and run ML models. The MLflow backend is exposed with default credentials.

Browsing to smarthire.htb/dashboard shows a model training interface. Uploading a CSV trains an ML model and the app names it after the logged-in user's email: user@domain.com-516fc2865d79-model. This name is important for the exploit.

Foothold — MLflow Pickle RCE

How it works

MLflow stores Python models as pickle files. When the app calls mlflow.pyfunc.load_model() to run a prediction, Python deserializes the pickle. The __reduce__ method executes arbitrary code during deserialization — before any MLflow-specific logic runs.

Key insight
The app loads the model tied to the logged-in user's account. The model name must match exactly what the dashboard shows — it's derived from the user's email address.
01
Get your model name

Log into smarthire.htb/dashboard, upload a valid CSV, and note the model name returned by the app.

02
Build and register the malicious model

The exploit creates a pickle payload using __reduce__ and registers it as a new version of your model in MLflow.

03
Trigger the shell

Upload a valid CSV to smarthire.htb/predict. The server loads your poisoned model, pickle fires, shell lands.

exploit.py — payload class
# The magic is in __reduce__ — fires on deserialization
class Payload:
    def __init__(self, cmd): self.cmd = cmd
    def __reduce__(self):
        return (os.system, (self.cmd,))

Privilege Escalation — .pth File Injection

Enumeration

sudo -l
svcweb@smarthire:~$ sudo -l
User svcweb may run the following commands:
    (root) NOPASSWD: /usr/bin/python3.10 /opt/tools/mlflow_ctl/mlflowctl.py *

Reading mlflowctl.py reveals the vulnerability. The script calls site.addsitedir() on every subdirectory inside a plugins/ folder, then imports modules from those directories as root.

mlflowctl.py — vulnerable section
# Iterates plugin subdirs and adds them to sys.path
for path in PLUGINS_DIR.iterdir():
    if path.is_dir():
        site.addsitedir(str(path)) # <-- executes .pth files here
 
# Then imports from those dirs as root
import mlflow_actions, backup_models

The vulnerability

site.addsitedir() does more than add a path — it also executes any .pth files found in that directory. Lines starting with import in a .pth file are executed immediately by Python. Since the script runs as root, code in those files runs as root too.

Root cause
The plugins/dev/ directory is writable by svcweb. Any .pth file placed there is executed as root the next time the script runs.
01
Write the malicious .pth file

Drop a .pth file into the writable plugins directory with a payload that sets the SUID bit on bash.

02
Trigger as root via sudo

Run the script with sudo — site.addsitedir() processes the .pth file and executes the payload as root.

03
Get root shell

The SUID bash binary lets you spawn a root shell with -p to preserve effective UID.

privesc
# Drop the payload
svcweb@smarthire:~$ echo "import os; os.system('cp /bin/bash /tmp/rootbash && chmod +xs /tmp/rootbash')" \
  > /opt/tools/mlflow_ctl/plugins/dev/exploit.pth
 
# Trigger as root
svcweb@smarthire:~$ sudo /usr/bin/python3.10 /opt/tools/mlflow_ctl/mlflowctl.py status
[+] MLflow service status: active

Lessons

Never allow untrusted users to register MLflow models — pickle deserialization is inherently unsafe and there is no safe way to load an untrusted pickle file.

site.addsitedir() executes .pth files — calling it on user-writable directories inside a privileged process is equivalent to giving that user a root shell. Sudo rules with wildcard arguments compound this further.
